## What the maker was asked to do
From issue #93, verbatim:

> `src/axon/http/app.py` has no auth on any route (/v1/chat/completions, /api/*, /dashboard).
> Default bind is 127.0.0.1 (safe), but `--host` is free with no warning. If set to 0.0.0.0
> (e.g. to let gnomon-eval hit it remotely per EVALUATING_AXON), anyone on the network
> triggers paid LLM calls (cost/DoS) and reads telemetry/dashboard.
>
> Fix: Optional bearer token via env, checked in a FastAPI `Depends`; warn (or refuse) when
> --host is non-loopback without a token set.
>
> Acceptance:
> - [ ] token-protected routes when the env var is set
> - [ ] non-loopback --host without a token warns or fails closed

The loop chose REFUSE over warn, with a tested `--allow-unauthenticated` /
`AXON_HTTP_ALLOW_UNAUTHENTICATED=1` escape hatch. Rationale is in the PR body.

## What to look for
Findings the same-family reviewers would be least likely to catch. Do not re-litigate style
or re-run the gate - both already passed. Prefer: correctness under inputs the tests do not
generate, security consequences of the chosen approach, and assumptions the diff makes about
the environment. Specifically worth a second vendor's eyes:

1. `_require_bearer_token` parses the header with `authorization.split(" ", 1)`. Consider
   inputs the tests do not generate: multiple spaces, tabs, a repeated `Authorization`
   header, an empty header, very long credentials, header-encoding edge cases in Starlette.
2. The dependency is registered via `FastAPI(dependencies=[...])`. Is there any route or
   sub-application that bypasses app-level dependencies besides the known `/openapi.json`
   and `/docs` (documented as a limitation)? Exception handlers, redirect responses,
   mounted static apps, the `_no_store` middleware ordering.
3. `_is_loopback` treats an unparseable host as non-loopback (fail closed). Consider hosts
   the tests do not cover: IPv6 with a zone id (`::1%lo0`), bracketed forms (`[::1]`),
   `0177.0.0.1` and other legacy octal/decimal spellings, an empty string, trailing dot.
   Does uvicorn accept any spelling the guard would wrongly refuse, or wrongly allow?
4. The env vars are read per request (token) and once at startup (the guard). Is there a
   TOCTOU or a reload interaction - `--reload` respawns workers, does the guard still hold?
5. Whether "refuse" is the right call at all, given the escape hatch exists, and whether the
   escape hatch's truthiness set is too narrow or too wide for real operator habits.

## What the diff does

Repoints the profile (renamed `free` -> `budget`, `free` kept as a registry alias) at four ids each
verified with a real litellm chat completion on 2026-08-26. Tier ladder: bottom
`deepinfra/meta-llama/Meta-Llama-3.1-8B-Instruct-Turbo`, mid
`openrouter/meta-llama/llama-3.3-70b-instruct`, top `deepinfra/meta-llama/Llama-3.3-70B-Instruct-Turbo`.

rungs silently disables that tier's fallback (issue #100). The provider split sits between top and
mid so the top-tier failover crosses providers with ZERO change to `engine.py`.
`provider_for_model` gains a `deepinfra/` branch; `llm_backend._KNOWN_PROVIDERS` gains the prefix.
`engine.py`, `runtime.py` and `judge.py` are byte-identical to master.

## What to look for

Findings the same-family reviewers would be least likely to catch. Do not re-litigate style and do
not re-run the gate - both passed. Prefer these, in order:

1. **The provider-string contract.** `provider_for_model` now returns a fifth value, `"deepinfra"`.
   Grep every consumer of its return value across the repo, not just `engine.py`, and check whether
   any of them switch on an exhaustive set of provider names, key a dict without a default, or feed
   the string into a metric label, a policy lookup or a persisted row. `engine.py`'s
   `provider_enabled` dict relies on `.get(provider, True)` and `spec_from_env` builds
   `AXON_{PROVIDER}_MAX_RPM` by string interpolation - both fine - but a third consumer that
   assumes a closed set would fail quietly.
2. **Whether `deepinfra` defaulting to ENABLED and UNCAPPED is the right default here.** It follows
   the `groq`/`nvidia_nim` precedent, but those were free tiers. DeepInfra bills. An uncapped,
   always-enabled billing provider reachable from the DEFAULT profile is a different risk shape
   than an uncapped free one. Is `AXON_DAILY_BUDGET` / `_OPUS_BUDGET` actually load-bearing here,
   given `daily_cost()` reads Langfuse over HTTP with a 1.0s timeout and returns 0.0 on any
   failure - i.e. the budget guard silently reads zero spend whenever Langfuse is absent?
3. **The `max(input, output)` cost scalar.** It multiplies PROMPT tokens only
   (`engine.py:333`, and `len(task.content)/4000` at lines 129/165 - note those two use a different
   token estimate than `count_tokens_for_progressive`/`count_tokens_for_provider`). Does any
   downstream consumer treat `cost_per_1k` as an input rate specifically, or reconcile it against
   real provider billing? If so, deliberately over-stating it could skew an attribution report
   rather than just a guard.
4. **Environment assumptions.** The profile now requires `DEEPINFRA_API_KEY` and
   `OPENROUTER_API_KEY` on the DEFAULT path, where previously the default needed `GROQ_API_KEY` and
   `NVIDIA_NIM_API_KEY`. `GROQ_API_KEY` is still required for the classifier. What is the failure
   mode on a machine that has only the old two - a clear refusal, or a litellm exception surfacing
   as "judge unavailable", i.e. exactly the symptom #154 was filed for? Check whether anything
   validates key presence per active profile rather than per call.
5. **The `_REGISTRY` alias aliasing an OBJECT, not a copy.** `{"budget": _BUDGET, "free": _BUDGET}`
   makes `get_profile("free") is get_profile("budget")` true. `ProfileSpec` is
   `@dataclass(frozen=True)` but its `models` and `cost_per_1k` are plain mutable dicts, and
   `engine.py` copies only `cost_per_1k` (`dict(_PROFILE.cost_per_1k)`) while `_MODEL_MAP` is built
   fresh. Is there any path - a test, a CLI, an MCP tool - that mutates a returned spec's dicts in
   place and would now corrupt both names at once?
6. **The CI assertion change.** `assert _PROFILE is get_profile('${{ matrix.profile }}')` replaced a
   name comparison. Identity holds because the registry stores one object per spec. Would it also
   hold under any plausible future change (a spec constructed per call, a frozen-dataclass copy, a
   profile loaded from config)? If not, the smoke job would fail for a reason unrelated to what it
   is testing. A weaker-but-stabler form would compare `.name` against `get_profile(...).name`.

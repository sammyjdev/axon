## What the maker was asked to do

`seed_corpus` in `src/axon/lessons/seed.py` is a coroutine with no caller. Nothing in the CLI, the MCP server or any hook invokes it.

The consequence, measured on 2026-08-22: the `lessons` table held 0 rows while `~/.claude/agents/forge/lessons/agent-errors.json` held 18. `axon_search_lessons` answered `no lessons matching` for every query - including a paraphrase of a lesson sitting in the corpus file. The feature had been on master since 2026-08-21 with a full green gate the whole time, because every test around the seed passes against a store the tests populate themselves.

Seeding it by hand took a scratchpad script that wires `_get_lesson_store()`, `_get_embedder()` and `axon_record_lesson.fn` together. That script is not in the repo and will not be there next time.

Done when: `axon seed-lessons [--corpus PATH]` exists, defaults to the shipped corpus path, and prints one status line per entry. The idempotency `seed_corpus` already implements must survive at the command level: a second run in a row must report every entry as unchanged and issue zero embedding calls - assert it with a spy, not with a row count, since a row count cannot tell a skipped entry from a re-embedded one.
